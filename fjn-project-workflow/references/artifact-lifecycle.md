# 实验产物生命周期（非版本规则）

产物清理不能驱动版本号，也不能删除版本记忆。目标是释放无用实验的大文件，同时永久保留每个实验的结论、证据和最小复现脚本。先把结论和证据写入项目总控，再讨论存储清理；本控制器没有自动删除功能。

## 每次实验完成后的必做标记

每个终态 run（含失败、取消和重试）检查结果后，显式评估其产物保留价值。判断对象是该 run 的大文件，不是删除实验目录。无可删项也必须登记，不只在最终交接时泛泛说明。

- `keep`：仍有价值或受保护，`files` 为空。
- `delete_candidate`：已确认未达标、没有后续用途、非历史主线、从未固化交付、不被受保护实验依赖，且复现材料齐全；逐项列未来删除候选文件。
- `needs_review`：用途、依赖或复现条件尚不能确认；写清待核实事项。

使用 [JSON 模板](../templates/artifact-review.example.json)，通过 `record-artifact-review --project-root <project> --run-id <run> --review-file <relative-file>` 追加登记。控制器生成 `docs/project-control/ARTIFACT_REVIEW.md`，展示每个 run 的标记、理由、候选文件与总字节数；新 run 未评估时明确显示“待评估”。旧 run 不强制批量补录。

记录包含 `schema_version: 1`、`run_id`、`assessed_at`、`review_after`、`decision`、`reason`、`checks`、`preserve` 和 `files`。`checks` 精确覆盖 `failed`、`no_future_use`、`not_historical_mainline`、`never_delivered`、`no_protected_dependents`、`reproducible`，各项有布尔值或 `unknown` 和 `reference::claim` 证据。删除候选要求六项均为 true；不确定时使用 `needs_review`。标为未达标须依据结果，不能用进程报错代替科学判断。

`preserve` 列出现存结论、关键证据和最小复现入口。`files` 每项记录项目相对精确文件 `path`、`size_bytes`、`mtime_ns`、`reason`、`rebuild`；只登记本 run 目录内的普通文件，不用目录或通配符，不列共享资产、保留文件或已登记证据。

`assessed_at` 不早于终结时间，`review_after` 至少晚七天。新实验当前仍属于近期活动保护范围，这只是为一周后集中清理准备的候选清单，**不代表现在可删，也不代表到期自动可删**。集中清理前必须按以下完整规则重新核实；新增用途或依赖应追加新评估改判，不能覆盖旧记录。控制器不删除文件，也不启动定时删除。

## 无用实验的判定

只有同时满足以下全部条件，才能按无用实验清理大文件：

1. **未达标**：有验收合同和实际指标证明未满足要求，或已有明确的未达标结论。`completed`、`abandoned`、报错中断、未晋级或没有指标本身均不能证明未达标；结论不足时标为待核实。
2. **不是近期活动实验**：不在运行、续训、排队、评估或交付中，也不属于当前任务、近期研究计划或明确待恢复的实验。结合活动任务、进程、运行状态与交接记录确认；项目有近期时间窗时记录该窗口，没有时不能自行仅按目录日期或 mtime 判定。
3. **不是历史主线实验**：未进入当前或任何历史主线、基线链。被新版本替代不取消此项保护。
4. **从未固化为交付版本**：从未被验收并固化、冻结、发布或打包为交付版本；交付后被替代仍受保护。单纯一次实验验收通过不等于固化交付，但该实验不满足“未达标”条件，也不能按无用实验处理。
5. **不是受保护实验的依赖**：不被上述近期活动、历史主线、曾固化交付三类实验直接或间接依赖，包括数据处理结果、checkpoint、payload、delta、refiner、缓存、专用代码快照和复现必需状态。

清理前列出三类受保护实验及其证据，沿实际配置、命令、manifest、加载路径和版本来源检查传递依赖，不能只靠版本号、名称相似或一次字符串搜索推断。依赖不明、缺少来源、共享归属不清或存在唯一不可重建副本时先保留并标记待核实。归档状态不代表获得删除资格。

这些条件适用于 smoke、失败重跑和正式运行；smoke 仍是 run，不是版本。源数据、人工资产、交付物和未解决故障的最小复现产物不属于本流程的默认清理对象。

## 每个实验必须保留的最小复现包

允许复用已有文件，无须复制完整仓库或原始数据，但每个实验必须有可独立理解的入口，永久保留：

- **结论与证据**：实验身份、目的、基线、实际改动、验收标准、未达标原因、最终结论；原始指标、计时边界与阶段耗时、关键日志和必要的代表性小图。永久保留版本/运行总账及其结论证据，不能只留下汇总数字或已失效链接。
- **最小复现脚本**：可运行的脚本或已有脚本加完整调用入口，覆盖该实验实际采用的预处理、前馈、优化、评估及必要导出步骤。保存完整配置、超参数、随机种子（若使用）和工作目录/环境说明，不能只有无法恢复参数的命令片段。
- **代码身份**：仓库及 commit、脚本入口和环境/依赖版本；未提交改动必须保存 patch 或必要源码快照。只有 commit 名称而对应实现已丢失，不算可复现。
- **输入与依赖清单**：数据集/场景/帧/相机划分、权重和上游状态来源、路径或持久下载地址、必要身份校验信息、生成命令和依赖关系。引用的共享文件必须持久保留且可定位；不能依赖本次清理将删除的文件而不提供重建路径。

清理前检查复现入口、参数和全部依赖是否齐全，并确认拟删除的中间状态能由保留内容重建。通常无需重跑昂贵实验；未实际复跑时明确写“复现材料已核对，未复跑”，不得宣称已验证数值复现。缺少唯一权重、代码或输入时先补齐，不能补齐则保留相关文件并报告限制。

## 大文件清理流程

1. 确认实验终态、结论和证据已入总账，逐项记录上述清理资格与依赖核对结果。
2. 完成最小复现包后，生成精确清单：文件路径、类型、大小、用途、删除理由、重建方式、预计可释放空间及保留项。大型 checkpoint、重复渲染、逐帧图像、中间 payload、临时缓存等只是候选，不能仅按扩展名或体积批量删除。
3. 确保清单不包含受保护实验及其依赖，不会删掉复现包、唯一证据或破坏已登记验收证据。引用拟删除产物的普通报告需保留原路径及清理说明；不可变版本快照、既有总账和历史验收证据不得覆盖改写。
4. 在用户已授权的范围内执行。用户已明确授权按这些条件清理时，无须重复索取同一授权；只有分析/制定计划的请求不授权删除。本 skill 的控制器不会自动执行删除。
5. 按精确清单操作，优先可恢复方式；记录实际处理结果和释放空间，核对保留文件、复现入口和依赖仍然有效，再运行项目 guard。若已登记证据使 guard 不通过，先保留该文件或通过受支持的控制面操作处理，不能删除后通过篡改历史账目消除报错。

不删除整个实验目录来代替产物瘦身。近期活动、历史主线、曾固化交付的实验及其依赖不纳入“无用实验”清理；若用户另行要求处理这些资产，应单列具体范围，不能套用本规则扩大删除权限。

## 清理记录

清理属于独立布局/资产事件，不得伪装成新版本，也不能手改控制器的总账或生成视图。在持久清理记录中保存：

- 实验身份、清理资格、受保护实验与传递依赖核对依据；
- 保留项和最小复现入口，以及保留原因；
- 拟处理与实际处理的精确文件清单、大小、理由、处理方式和释放空间；
- 用户授权来源、清理时间、可恢复性和恢复位置（若有）；
- 结论、指标与原始计时证据的位置，复现核对结果、未复跑说明或已知限制；
- 删除后的依赖/引用检查和 guard 结果。
