# 多级文件夹规划与重构规则

## 1. 目录是业务语义，不是版本字符串容器

受管目录使用以下层级：

```text
project
  -> area / workstream
    -> experiment_family
      -> candidate
        -> run
          -> artifact
```

可按需要省略 `area`，但不得跳过候选直接把 seed、日期、smoke 和 full 都堆成实验版本。

| 层级 | 回答的问题 | 典型内容 |
|---|---|---|
| `project` | 这个项目边界是什么 | 项目根 |
| `area` | 哪类业务资产 | 输入、算法、评估、交付、平台工程 |
| `workstream` | 哪条长期工作线 | MapAnything 初始化、PBR 优化、预览平台 |
| `experiment_family` | 哪一类可连续比较的问题 | 深度校准、体素压缩、mask 消融 |
| `candidate` | 当前基线下哪个独立假设 | `MA-v7-a` 对应的候选目录 |
| `run` | 某次具体执行 | smoke、full、seed、参数点 |
| `artifact` | 运行产物属于哪类 | checkpoints、metrics、visuals、logs |
| `archive` | 不再活跃但必须保留的资产 | 历史只读资料 |

首次出现的不常见术语应在文件夹职责中解释，不能只写参数缩写。

## 2. 每次新增目录前必须先回答

1. 它属于哪个作用域和工作线？
2. 它是已有实验族的新候选，还是新的实验族？
3. 它只是一次重跑/seed/参数点吗？若是，只建 `run`。
4. 父目录的直接子目录是否都承担同一种层级职责？
5. 新目录是否让父目录超过活跃平级预算？
6. 是否存在名称语义重复、路径过深或“final/latest/new”命名？
7. 应该复用、建直接子级、新增语义分组、局部重构还是大范围重构？

必须先运行 `plan-layout`。只有记录布局决策后，才能注册或由控制器创建目录。

## 3. 平级预算

默认同一父目录最多有 6 个活跃的同层 `experiment_family` 或 `candidate`。

第 7 个之前优先：

1. 按独立问题拆成新的 `experiment_family`；
2. 按长期业务线拆成 `workstream`；
3. 将完成项标为 `archived` 或 `superseded`，但不能删除其历史；
4. 提出 `local_restructure` 或 `broad_restructure`。

例外必须填写 `override_reason`，脚本会把理由写入永久事件。豁免只允许说明“为什么暂时保持平级更清楚”，不能写“方便”“先这样”。

平级预算不计算 run、seed、日期批次或 artifact；这些必须位于候选之下。

## 4. 五种布局动作

- `reuse`：复用已登记目录，不创建重复目录。
- `new_child`：在当前父级下建立一个职责明确的直接子目录。
- `new_group`：先引入新的语义分组，再把候选放入其中。
- `local_restructure`：只调整一个工作线或实验族的内部结构。
- `broad_restructure`：多个工作线职责混淆，需要重新规划较大范围结构。

`new_group`、`local_restructure`、`broad_restructure` 只记录决策，不自动搬动旧数据。具体迁移必须另行规划并经用户确认。

## 5. 目录名规则

1. 一个候选目录最多出现一个候选身份。
2. run 目录不得包含新版本号；使用生成的 `run_id` 或稳定 variant。
3. 禁止 `final`、`latest`、`new`、`newer` 作为身份语义。
4. 日期是运行属性，不是实验族分类轴。
5. 不在 basename 中堆叠来源版本，例如禁止 `v23_v22_l2f_v2_final`。
6. 上游依赖、基线与来源写入总账字段，而不是继续拼到目录名。
7. 每个登记目录必须有一句可独立理解的业务职责。

## 6. 什么时候重构

### 新建子级

- 父目录职责仍稳定，只缺一个新的实验族或候选容器。
- 现有路径引用不需要改变。

### 局部重构

- 一个实验族内混入候选、run、产物三种层级。
- 同层职责不一致。
- 平级候选超过预算。
- 名称不能再表达业务差异。

### 大范围重构

- 项目级、工作流级和实验级共用同一个版本空间。
- 多条长期工作线相互嵌套或交叉写入。
- 多个关键入口不能回答“当前真相在哪里”。
- 目录被绝对路径、训练配置或外部服务大量引用。

大范围重构必须先做只读依赖盘点、迁移映射、回滚方案和用户确认。本 skill 的控制器不会自动移动现有项目。

## 7. 目录职责登记与审计

`DIRECTORY_MAP.md` 是由 `state.json` 生成的人读视图。控制器保存：

- 路径与层级；
- 唯一职责；
- 父目录与作用域；
- 活跃/归档/被替代状态；
- 是否要求直接子目录全部登记；
- 对应布局决策与豁免理由。

对设置了 `manage_children` 的目录，guard 会报告磁盘上存在但未登记的直接子目录。它不会自动删除或移动它们。
