# fjn-project-improvement-loop 维护记录

本文件只用于维护 skill 自身的演进，不属于运行时推理材料。使用该 skill 时不自动读取本文件；只有维护、审查或升级 skill 时才读取。

版本号表示 skill 行为契约的变化，不表示项目实验版本，也不改变项目内 `docs/improvement-loop/` 的轮次编号。

## 1.1.0 — 2026-11-05

### 改动

- 将根因分析明确为沿处理链定位异常首次出现的环节，并区分推测、观测支持和干预验证。
- 将最小实验定义为能以必要的最少变化区分解释，而不只是成本最低或代码改动最少。
- 要求在方案预期中写出本轮局部验收标准，并在结果中分别记录局部效果、整体影响和根因判断更新。
- 将泛化表述提升为共同机制原则：方案应避免不必要依赖个例身份、位置或特征；独立样例检查由执行者按任务判断，不设固定强制门槛。

### 设计影响

- 复用现有 `root_cause`、`expected_observation`、`mechanism_check`、`evaluation` 和 Critic 检查。
- 没有新增阶段、账本、必填字段或运行时读取路径。
- 局部成功不能替代最终验收；有效负结果仍可作为假设裁决进展。

### 验证

- improvement-loop 现有测试：45 项通过。
- 维护前已有的 skill frontmatter 校验兼容问题保持不变：通用校验器不接受原有 `argument-hint` 和 `user-invocable` 字段；本次未扩大该问题。

### 已知不足

- 代码只能检查字段、引用和逻辑一致性，不能自动证明根因、局部验收或泛化判断正确；这些仍由原始证据和 Critic 审查完成。

## 1.0.0 — 基线记录

基线为本维护记录建立前的现有六阶段 improvement loop：包含目标评估、方案设计、Workflow 执行、结果评价、方案树演化和产物价值评估，以及 decision contract、独立 Critic 和停滞重定根控制。
